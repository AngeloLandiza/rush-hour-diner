# Rush Hour Diner: sub-agent development prompt

*How to use: start a Claude Code session in the `rush-hour-diner` GitHub repo and paste everything below the line as the first message (or save it as `CLAUDE.md` plus `docs/ORCHESTRATOR.md` in the repo). It's written for the orchestrating Claude.*

---

## 0. Your role

You are the **orchestrator** for Rush Hour Diner, a Roblox co-op restaurant tycoon built entirely as code with Rojo, GitHub and VS Code. You own the architecture, the shared contracts, integration, and the final quality bar. You delegate bounded, parallel work to sub-agents and keep your own context small: you read **diffs and reports**, not whole files.

**Definition of done for the MVP:**

- The place builds with `rojo build`, passes lint, types and tests in CI, and auto-publishes through Open Cloud.
- A new player can join, cook and serve within 60 seconds.
- Saving, all purchases, the hourly Rush Hour and legendary customers work.
- There are no exploitable client-trusted values.

## 1. Product spec (the source of truth, don't re-ask)

**Pitch:** 1–4 friends run a tiny meme-food stand that grows into a chaotic diner. Hourly **Rush Hours** flood customers in. Rare **Legendary Customers** tip huge and trigger a server-wide announcement. That announcement is the clip moment.

**Core loop (first cycle under 3 minutes):** a customer arrives, sits and shows an order bubble. A player grabs the ingredient, cooks at a station (a timed minigame of hold, flip and collect), plates the dish and serves it. The customer pays coins plus a tip, and the tip scales with speed and combo. Coins buy upgrades.

**MVP content:**

- **One plot per player:** up to 6 plots per server, and friends can join a plot as crew.
- **4 stations:** Grill (burger), Fryer (fries), Oven (pizza), Soda Fountain (drink).
- **12 upgrades:**
  - station speed ×4
  - customer patience
  - seating capacity ×3
  - tip multiplier ×2
  - auto-server bot
  - decor tiers ×2, which raise tip %
- **Customers:**
  - Regular: R15 default bundles with randomized free outfits
  - Hungry: impatient, pays 1.5×
  - VIP: 3× pay
  - **Legendary** (3 at launch): Giant Chef, Space Alien, plus a **weekly meme slot** driven entirely by config
- **Rush Hour:** every hour at :00 server time, for 4 minutes, at 3× spawn rate and 2× pay. A visible countdown is always on the HUD.
- **Retention:**
  - daily streak (days 1–7 rewards)
  - ingredient restock timer: offline earnings capped at 8h, needing a return to collect
  - Rush Hour countdown
  - "next menu drop" weekly countdown
- **Crew bonus:** +10% coins per crew member on the same plot, up to +30%.
- **Leaderboards:** lifetime coins (global OrderedDataStore) and best Rush Hour (server).

**Monetization** (IDs live in `Config/Products.luau`, with placeholder IDs until created):

- **Game passes:** 2× Tips, Auto-Chef (AFK income while in game), Extra Station Slot, VIP Booth (cosmetic and a chat tag)
- **Developer products:** Instant Restock; Rush Hour Now (server-wide, with the buyer credited in the announcement); Tip Potion 15 min (+50%, and the effect is shown numerically); 3 coin packs
- **Rewarded video ad:** watch for a +25% tip boost for 10 minutes. Opt-in only.
- **No paid random items in the MVP.** If any get added later, they must follow the odds-disclosure and `PolicyService` rules.

**Hard constraints:**

- **R15 avatars only** (StarterPlayer settings), for the U.S. 18+ DevEx rate.
- **Server-authoritative everything:** coins, cooking completion, serving and purchases.
- `ProcessReceipt` must be idempotent: record the receipt ID in profile data and return `PurchaseGranted` only after the save is confirmed.
- **No video feeds, autoplay or scroll-for-reward mechanics.**
- **No copyrighted names, characters, music or logos.** Audio is either generated by us or from Roblox's own licensed library.
- **All player text** (crew names, signs) passes through `TextService:FilterStringAsync`.

**Art direction ("code-first stylized"):**

- **Materials:** SmoothPlastic and Neon with a bright, saturated palette.
- **Palette** (`Config/Palette.luau`, the only source of colors): cream `#FFF4E0`, ketchup `#E63946`, mustard `#FFB703`, mint `#2EC4B6`, ink `#1D3557`, neon pink `#FF5DA2`.
- **Shapes:** chunky rounded geometry (parts plus `CornerWedge`, cylinders and spheres) and slightly oversized props.
- **Lighting:**
  - Future lighting, with an Atmosphere preset and ColorCorrection
  - a warm daytime preset
  - a **Rush Hour preset** that tweens to a saturated, neon, high-contrast look and back
- **UI:** built 100% in code (Frame, UICorner, UIStroke, UIGradient), with a bouncy tween library, a big readable font (FredokaOne or GothamBlack), and mobile-first touch targets of at least 44px.
- **VFX:** ParticleEmitters for steam, sizzle, fire and the coin burst, plus a tip "explosion" that scales with tip size.

## 2. Repo, toolchain and conventions (built by you in Wave 0)

```
rush-hour-diner/
  default.project.json          # Rojo 7 tree
  rokit.toml                    # rojo, wally, selene, stylua, luau-lsp, lune pinned
  wally.toml                    # ProfileStore (vendor in Packages/ if not on Wally), Promise, Signal, Trove
  selene.toml / stylua.toml / .luaurc (strict mode)
  src/
    shared/                     # ReplicatedStorage.Shared
      Contracts/                # ⚠ OWNED BY ORCHESTRATOR ONLY
        Types.luau              # PlayerData, Order, Customer, StationState, UpgradeDef…
        Remotes.luau            # every RemoteEvent/Function name + payload type
        Events.luau             # server-internal Signal names
      Config/                   # data-only tables: Stations, Dishes, Upgrades, Customers, Products, Palette, Lighting, Timings
      Logic/                    # PURE functions, no Roblox services → unit-testable in Lune
        Economy.luau  Orders.luau  Upgrades.luau  Offline.luau  Streak.luau
    server/                     # ServerScriptService.Server
      Services/  DataService  PurchaseService  PlotService  CustomerService  StationService
                 RushHourService  LeaderboardService  AnalyticsService
      World/     MapBuilder  PropBuilder  LightingDirector  AudioDirector
      init.server.luau          # boots services in order
    client/                     # StarterPlayerScripts.Client
      Controllers/ InputController  StationController  HUDController  ShopController  FXController
      UI/          Theme.luau  Components/ (Button, Panel, Toast, Countdown, ProgressBar)  Screens/
      init.client.luau
  assets/        # generated sounds/images + manifest.json (asset name → uploaded rbxassetid)
  tools/         # Lune scripts: run tests, economy simulator, asset upload, publish
  tests/         # Lune unit tests for src/shared/Logic
  .github/workflows/ci.yml       # lint + types + tests on PR
  .github/workflows/publish.yml  # on push to main: rojo build → Open Cloud place publish
  docs/  GDD.md  ARCHITECTURE.md  ECONOMY.md  CHANGELOG.md
```

**Conventions:**

- Every service and controller is a ModuleScript exposing `Init()` then `Start()`.
- **Services talk to each other only through `Contracts/Events.luau` signals,** or through the documented public functions listed in `ARCHITECTURE.md`.
- **Client and server talk only through `Contracts/Remotes.luau`.** Validate every remote argument on the server: type, range, rate limit, and ownership of the plot or station.
- All numbers live in `Config/`. No magic numbers in services.
- Use `--!strict` everywhere. StyLua formats on commit.

**Publishing:**

- `publish.yml` runs `rojo build -o place.rbxl`, then POSTs the file to `https://apis.roblox.com/universes/v1/{UNIVERSE_ID}/places/{PLACE_ID}/versions?versionType=Published` with header `x-api-key: ${{ secrets.ROBLOX_API_KEY }}`.
- Assets are uploaded with `tools/upload_assets.luau` through the Open Cloud Assets API, which writes the IDs into `assets/manifest.json` and then into `Config`.
- **Secrets are never committed.** The universe ID and place ID live in repo variables.

## 3. Sub-agent operating rules (efficiency)

1. **Contracts first, then fan out.** Nothing parallel starts until Wave 0 has merged `Contracts/`, `Config/` stubs and `ARCHITECTURE.md`. Parallel agents code against the contracts, not against each other.
2. **Exclusive file ownership.** Every agent brief lists the directories it may write to. Agents never edit `Contracts/` or another agent's files.
   - If an agent needs a contract change, it says so in its report and you apply it.
   - Because ownership is disjoint, agents work on the same branch without worktrees. Use `isolation: "worktree"` only when two agents must touch the same area.
3. **Briefs are self-contained and minimal.** Each brief contains:
   - the goal
   - its spec slice, copied from section 1
   - the paths to read (`Contracts/*`, its `Config` files, `ARCHITECTURE.md`)
   - the files it owns
   - its acceptance checks
   - the report format

   Never paste whole files into a brief; give paths.
4. **Agents verify before returning.** Each agent runs `stylua --check`, `selene src`, `luau-lsp analyze` and `lune run tools/test` for anything in `Logic/`. **An agent doesn't return until its own checks pass,** or it reports exactly why they can't.
5. **Report format, under 200 words:**
   - files created or changed
   - public API added
   - checks run and their results
   - contract change requests
   - known gaps

   No code dumps. You review with `git diff --stat` and targeted reads.
6. **Model and effort tiers:**
   - **`opus`:** architecture and Wave 0 (you), integration, and the security and compliance review
   - **`sonnet`:** gameplay services, UI, world building and data/purchases (the default for code)
   - **`haiku`:** data-entry config tables, copywriting variants, asset manifest bookkeeping and docs formatting
7. **Concurrency:** at most 5 agents at once. Launch a whole wave in **one message** so the agents run in parallel. Don't start the next wave until you've reviewed and merged every report from the current one.
8. **One commit per agent task,** message `feat(<area>): …`. Review the diff, run the full CI checks locally, then push.
9. **Don't redo delegated work.** If a report is wrong, send a corrective follow-up to the same agent with `SendMessage` and the exact failing check, rather than re-implementing it yourself.
10. **Studio access is optional, not blocking.** If the Roblox Studio MCP server is connected (through Remote Control on the user's computer), use it for playtests, console errors and screenshots. If not, rely on Lune tests plus the user's screenshots.

## 4. Waves

### Wave 0 (orchestrator, solo, about half a day)

- Scaffold the repo tree, toolchain, CI workflows and placeholder publishing.
- Write `Contracts/Types.luau`, `Remotes.luau` and `Events.luau`, with every type and remote the MVP needs.
- Write `Config/` stubs with the final keys and placeholder values.
- Write `ARCHITECTURE.md`, covering the service boot order, the public functions per service, and the data flow for "serve dish → pay".
- Write `GDD.md` from section 1.
- **Commit and push. CI must be green on empty services.**

### Wave 3 (fresh review, then fixes)

- **I. Security & compliance review** (opus, fresh context, given only the repo and this checklist, *not* your conclusions):
  - Can a client grant itself coins, finish cooking early, serve another player's order or claim another plot?
  - Is any remote missing validation or rate limits?
  - Is `ProcessReceipt` idempotent?
  - Can data be lost on leave or shutdown (BindToClose)?
  - Are avatars R15-only?
  - Are there no scroll or video-feed rewards, no copyrighted assets, and is all text filtered?

  It reports findings ranked by severity.
- **Fixes:** you route each finding to the original owner agent as a follow-up. Re-run CI, then merge to `main`, which auto-publishes.

## 5. Acceptance checklist (you sign off)

- [ ] CI is green: StyLua, Selene, luau-lsp strict and Lune tests.
- [ ] `rojo build` succeeds and the publish workflow uploaded a new place version.
- [ ] A new player is cooking within 60 seconds, and the first upgrade comes in under 2 minutes in the sim.
- [ ] Data survives a rejoin and a server shutdown. Each purchase is granted exactly once.
- [ ] Rush Hour fires on the hour, and lighting and music switch with it.
- [ ] A legendary customer triggers the banner, the VFX and a large tip.
- [ ] Mobile layout works at 360×640.
- [ ] The review found no open high-severity issues.

## 6. Weekly update loop (after launch)

Run every week:

1. The user pastes Creator Dashboard numbers: D1, D7, D30, sessions per user, playtime, conversion and ARPDAU.
2. You compare them with the targets: **D1 30% or more, 1.5+ sessions per user per day, playtime 15 minutes or more.**
3. Pick **one** retention change and **one** content drop (a new dish, plus the weekly meme legendary customer in `Config/Customers`).
4. Fan out at most 2–3 agents with the same rules as above. Ship by Friday and have the update go live on Saturday.
5. The launch kit agent (haiku) writes 5 shorts scripts for the update.

## 7. What the user must do (ask once, then don't block on it)

1. Create the game in the Creator Hub. Copy the **universe ID** and **place ID** into repo variables.
2. Create an Open Cloud API key with **Place Publishing** and **Assets write** permissions for that universe. Save it as the repo secret `ROBLOX_API_KEY`.
3. Create the game passes and developer products listed in section 1 (names and prices are in `docs/LAUNCH.md`), then paste the IDs back.
4. Optionally connect their computer with Studio open (Remote Control plus the Studio MCP) so you can playtest and take screenshots.

Until these are done, build with placeholder IDs and keep CI publishing disabled behind a variable flag.
